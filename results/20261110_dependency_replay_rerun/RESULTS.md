# 何を再計算すれば、過去の編集を正しく取り消せるか

固定GPT-2 CPU FP32・著者ROME/MEMITの開発実験。6条件の分解、18組の時間比較、
8件・16件の履歴から計12回の選択的撤回を実施。新規性・一般能力・SOTAの証明ではない。

[事前手順](../../docs/DEPENDENCY_REPLAY.md) / [実行manifest](run.json) / [全結果](results.json) / [監査](audit.json)

## 1. Aの影響がBのどの計算に残るか

A→BからB、Aを厳密に巻き戻し、Bの内部目標とキー側計算を別々に再利用する。
ROMEでは内部目標と最終値因子を区別し、現在出力の差し引き・正規化を毎回計算する。
MEMITでは層ごとのキーと調整済みキーの線形求解を対象とし、現在状態に対する残差は毎回計算する。

| 方法 | ROME 全状態一致 | MEMIT 全状態一致 |
| --- | ---: | ---: |
| すべて再計算 | 3/3 | 3/3 |
| 内部目標だけ再利用 | 0/3 | 0/3 |
| キー側だけ再利用 | 3/3 | 0/3 |
| 内部目標＋キー側を再利用 | 0/3 | 0/3 |
| 更新全体を再利用 | 0/3 | 0/3 |
| 依存を確認して再利用 | 3/3 | 3/3 |

比較対象は「Aを与えず最初からBだけ編集したモデル」。
計測用アダプタの無再利用実行も、未改変の著者実装に全6条件で全状態一致した。

| 方式 / 組 | 内部目標の相対差 | キー側のbit一致 |
| --- | ---: | --- |
| rome / different_subjects | 1.18171 | key:5=True |
| rome / conflicting_targets | 1.34377 | key:5=True |
| rome / different_relations | 0.624081 | key:5=True |
| memit / different_subjects | 0.797266 | key:4=True, solve:4=True, key:5=False, solve:5=False, key:6=False, solve:6=False |
| memit / conflicting_targets | 0.68188 | key:4=True, solve:4=True, key:5=False, solve:5=False, key:6=False, solve:6=False |
| memit / different_relations | 0.423442 | key:4=True, solve:4=True, key:5=False, solve:5=False, key:6=False, solve:6=False |

## 2. 再利用条件と、確認を含めた実時間

内部目標は全モデルテンソル、キーは当該GPT-2層のc_proj入力までのテンソル、
線形求解は実際のキー・共分散に依存する。設定・要求・コード・固定資源も結び付ける。
live bytesのハッシュを毎回計算する保守的な実装。変更なし、上流変更、同層c_proj変更、
要求変更、キャッシュ破損、MEMIT共分散変更の実モデル対照を実施した。

| 方式 / 組 | 著者実装 秒 | 確認付き再利用 秒 | うち依存判定 秒 | 対応比の中央値 |
| --- | ---: | ---: | ---: | ---: |
| rome / different_subjects | 1.2466 | 1.5665 | 0.3175 | 1.304× |
| rome / conflicting_targets | 1.2031 | 1.5176 | 0.3280 | 1.261× |
| rome / different_relations | 1.2422 | 1.5342 | 0.3316 | 1.222× |
| memit / different_subjects | 1.3975 | 1.9003 | 0.6971 | 1.370× |
| memit / conflicting_targets | 1.7767 | 2.2500 | 0.6846 | 1.259× |
| memit / different_relations | 1.5268 | 1.9451 | 0.7271 | 1.358× |

各条件3回、順序を交互にして実行。比は「確認付き／著者実装」で、1より大きいと遅い。
時間には編集内の依存確認・値の検査・計算・重み適用を含む。共通の計測用全状態ハッシュ、
生成評価、アダプタ構築、artifact I/Oは除外。cache記録を伴う初回編集の計算時間もresults.jsonに保存する。
cache/復元記録の直列化・保存の時間はこの実験の速度比較に含めず、総運用費の測定とは扱わない。
「依存判定」は入力ハッシュと既存cacheの検査まで。新しい値のdigest作成など残りのcache管理費も総編集時間に含む。
単一端末・固定順序の小規模測定で、一般的な速度差や統計的優越性は主張しない。

### 編集品質と対照問

基準モデルが正答した対照4問についても、保持履歴の参照モデルで失敗が出た。
確認付き再利用はこの参照と同じ状態になるので、その失敗も同じように再現する。
今回の局所性・保持性能を成功とは扱わず、大型化による解消も仮定しない。

## 保存費用と検証範囲

| 方式 | 履歴長 | 正確な復元記録 bytes | 成分cache bytes |
| --- | ---: | ---: | ---: |
| rome | 8 | 2660124 | 140384 |
| rome | 16 | 5618924 | 280768 |
| memit | 8 | 4312704 | 965104 |
| memit | 16 | 9320268 | 1930208 |

共通のモデル・tokenizer・共分散、計測用の重みコピー・logit、実行中のRAMは上表の外。
復元記録には旧状態の丸め補正情報を保持する。情報なしの忘却・復元ではない。
同一の保存bytesはhard linkで共有するが、数値計算は実行する。大きな配列はgit対象外でローカル保持。
証明範囲は固定のeager GPT-2、eval、CPU、単一書き手、不変の非テンソル設定に限定する。
別モデル、適応する共分散、永続optimizer、外部の書き換え、別backendの保証には拡張していない。

監査: 456 binary、6 model、21 upstream、5実行元ファイル、414件の再利用判定。エラー0。

初回中断は対照群の保存メタデータ修正によるもの。途中ログ・artifactは残した。再実行と72組の既存測定を比較した（時間を除外）。

[保存配列の別処理による再検算](arrays-audit.json): 72比較、6著者実装一致、27成分差、160層の厳密復元、12件の古い更新再適用を確認。optimizerやforwardの追加再実行ではない。
