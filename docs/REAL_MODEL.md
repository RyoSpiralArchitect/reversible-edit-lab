## 入れ替え可能な部分

`core.py`の数値カーネルは任意の有限実行列に使えます。実モデルでは、編集対象のMLP出力射影を`(output_dim, input_dim)`の行列として取り出し、実際のforwardで得たキーと目標を渡します。`torch.nn.Linear`とGPT-2の`Conv1D`では重みの軸規約が異なることがあるので、形状の一致だけで決めず、元のforwardとの積の一致を確認します。

必要な接続点は次の三つです。

1. **キーの取得**：対象層のMLP中間活性、対象トークン位置、使用コンテキストを記録する。
2. **目標値の生成**：ROMEのvalue最適化、またはMEMITの残差配分から得た内部目標を使う。自然言語の正解文字列をそのまま行列に渡すものではない。
3. **状態の適用**：対象行列を更新した後、キャッシュ等を使い回さず、その重み状態からforwardを再計算する。

NumPyカーネルの`EditResult.delta`と`spec`のうち、選択した復元方式で必要なものだけを残します。実装上`EditResult`を丸ごと保持すると、更新済み行列・因子・specのすべてを保持するため、最小の実行時メモリにはなりません。NPZのreceipt出力は選んだ情報だけを書き出します。

## 初回の実LLM比較

単一編集、少数の事実、1層から始め、同じ編集を以下の復元方式で比較します。

- 変更された層のチェックポイントへ戻す評価基準。
- 実際に適用した低ランク因子を残して戻す。
- その因子に圧縮した丸め補正を添えて、元の保存ビットまで戻す。
- 補正データの予算を固定し、誤差の大きい位置だけを補正する。
- キー・目標を記録してsoft ROMEの解析逆変換。
- 原情報なしの固定ランクSVD。

対象事実、言い換え、近傍事実、無関係のテキスト上のKL、復元後の別の同一編集の結果を保存します。最適化していない固定目標の行列テストと、内部目標も最適化する実LLM編集の結果は分けます。

## v0.2の丸め補正を接続する

`make_receipt(original, edit_result, ...)`は書き込み時に、実際の編集前状態と、選んだ逆変換で予測される復元状態を比較します。`delta_exact`と`analytic_exact`は両者の保存ビットのXORを圧縮し、`delta_sparse`は予算内で選んだ位置の補正を残します。復元時の`restore_from_receipt`に元行列を渡す必要はありません。

これは編集前の情報を持つ方式です。完全な旧重み配列をそのまま保持しないことから、補助記録が常に小さいとは結論しません。比較には因子や共分散、補正ヘッダー、NPZのコンテナを含む実際の保存バイト数を使います。sparse方式の`patch_budget_bytes`は補正データ部の予算で、記録全体のサイズではありません。

補正を生成する前に、元の重みを実機で保持している形式と一致させます。v0.2のcorrected receiptは、宣言した精度に既に格納されたdtypeと値を要求し、暗黙の再量子化を拒否します。bfloat16はこのNumPy実装ではbfloat16の値だけを持つfloat32配列で表現します。実機の量子化重みや混合精度演算を使う場合は、その保存形式と丸め位置に合わせた接続が必要です。

補正は、復元候補となる逆変換の結果のビット列にも対応付いています。同じメタデータでも、BLAS、デバイス、演算順序などが変わってその結果が変われば、適用を拒否します。**異なる環境でも近い値が出ることと、同じ補正記録を厳密に適用できることは別の条件**です。実機での接続時には、予測復元の演算を固定するか、同じビット列を再現できる実装を選んで検証します。

同じ予測復元を再現できる条件では、exact receiptは元のテンソルのdtype・形状・バイト列のハッシュまで一致させます。このためB→Aの順で戻すと、Aの記録が要求する中間状態も厳密に再現できます。次の例はhard ROMEをbfloat16で2回適用し、入力アーカイブと中間モデルを削除してから、編集後モデルと記録だけで戻します。

```bash
python examples/exact_chain.py --out demo_chain
```

結果の`evidence.json`には、中間状態と最初の状態の期待ハッシュ・復元ハッシュ、記録の実ファイルサイズを残します。元の重みそのものを推測する方式や、追加情報なしの復元を示す例ではありません。

## 多層MEMITと継続学習

各層のキーや目標は、その層より前の更新と関係します。最終モデルから再抽出した値を、編集時の値と同一と仮定しません。まず層ごとの実際の更新因子を記録して逆順に戻し、その後にメタデータだけで戻す方法を比較します。

また、重みを戻してもoptimizer state、KV cache、乱数状態、外部メモリが以前と同じとは限りません。復元後の学習経路を比べるときは、比較に影響する状態を揃えます。今回のNumPy実験にはこれらの隠れた状態はありません。

## 判定を分ける

1. 復元後に旧事実へ答えられる。
2. 元の重みや出力分布が近い。
3. 復元後の次の学習と問い合わせ先も近い。
4. 同じ問い合わせ・計算予算で最終的な課題性能が高い。

それぞれ別の結果です。v0.1は2と3を合成条件で検証し、4のための小さな比較実験を用意しました。v0.2のexact補正は、保存情報を追加した条件で2のビット単位の一致と逆順復元を検証します。これだけで実LLMの課題性能や情報選択の優位性が示されたとは扱いません。
